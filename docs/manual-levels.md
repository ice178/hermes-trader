# Ручные уровни и зоны через Telegram

`hermes-levels-bot.service` постоянно принимает команды. Сканер
`hermes-signals-bot.service` продолжает запускаться по своему таймеру. Они
используют один SQLite-файл; база находится вне Git-каталога.

## Команды

Команды доступны только пользователям из `TELEGRAM_ALLOWED_USER_IDS`.
Это числовые **user ID**, а не chat ID. Ответ приходит в чат команды;
уведомления о сигналах по-прежнему идут в `TELEGRAM_CHAT_ID`. В общем чате
ответ виден его участникам.

```text
/levels_add BTC/USDT bingx buy 4h level 65000 65500 66000 | Поддержка
/levels_add BTC/USDT bingx sell 1d day_high 67000 | Максимум дня
/zone_add ETH/USDT bingx buy 1h imbalance 3150 3200 | Зона интереса
/levels
/levels BTC/USDT
/level_delete BTC/USDT bingx 65000
/zone_delete ETH/USDT bingx 3150 3200
/help
```

Поддерживаются суффиксы `/levels@имя_бота`. Команды другому боту, изменённые
сообщения, обычный текст и сообщения неразрешённых пользователей игнорируются.
В группе используйте суффикс имени бота, если Telegram Privacy Mode не
доставляет команду без него. Демон не меняет настройки Privacy Mode.

Биржи и тикеры берутся из `src/hermes_trading/scanner_config.py` — того же
списка, который использует сканер. Сейчас это BingX и BTC/USDT, ETH/USDT,
SOL/USDT, XRP/USDT, NEAR/USDT. Регистр биржи и тикера нормализуется.

- Направление: `buy` или `sell`.
- Тип точки: `day_high`, `day_low`, `level`, `mirror`.
- Тип зоны: `imbalance`; нижняя граница строго меньше верхней.
- Таймфреймы: `1m`, `3m`, `5m`, `15m`, `30m`, `1h`, `2h`, `4h`, `6h`, `8h`,
  `12h`, `1d`, `3d`, `1w`, `1M`. `1m` — минута, `1M` — месяц.
- Цена: положительная десятичная запись через точку, до 24 цифр с каждой
  стороны точки. Экспонента, запятая и разделители тысяч не принимаются.
- Комментарий после `|` необязателен, максимум 500 Unicode-символов.

Невалидная команда не создаёт ни одной записи. Повторно добавленные активные
области пропускаются с указанием существующих ID. Другой таймфрейм или тип —
отдельная запись, другой комментарий — нет. `100` и `100.00` — одна цена.
Цены хранятся без преобразования в двоичную floating-point запись.

Удаление затрагивает **все** активные записи указанной биржи/тикера с точной
ценой точки или точными границами зоны, независимо от направления/таймфрейма.
Ответ перечисляет затронутые записи. Они остаются в базе со статусом `deleted`.
Повторное добавление создаёт новый ID. `/levels` показывает только активные.

## Отметки в сигналах

Используется включающий тени диапазон всех свечей паттерна. Границы включены;
у engulfing учитываются две или три свечи. Когда подходят обе формы, сохраняется
один сигнал с диапазоном трёх свечей. `buy` сопоставляется с LONG, `sell` — с
SHORT; биржа и тикер должны совпадать.

Таймфрейм уровня отображается как источник и не ограничивает таймфрейм сигнала.
Касание не удаляет область. Все совпавшие области перечисляются по цене/ID;
длинные сообщения разбиваются без разрыва записи, с повторением контекста.
HTML в комментариях экранируется; ответы на команды отправляются plain text.

Без совпадений сообщение остаётся прежним. Если задана `LEVELS_DB_PATH`, но база
недоступна или схема несовместима, сигнал отправляется с пометкой
`Manual levels: unavailable`; ошибка также отмечается в journald.
Пустая `LEVELS_DB_PATH` отключает обогащение сообщений.

## Первая установка на сервере

Сначала обновите код по [инструкции сервера](server-deployment.md).
Тесты запускаются локально: `python3 -m pytest`.

В существующем `/etc/hermes-trading/hermes-signals-bot.env` задайте:

```dotenv
LEVELS_DB_PATH=/var/lib/hermes-trading/levels.sqlite3
TELEGRAM_ALLOWED_USER_IDS=<user-id>,<another-user-id>
```

Замените placeholders реальными разрешёнными ID. Токен и chat ID остаются
существующими. Не копируйте `.env.example` поверх рабочего файла.

Установите оба service-файла (scanner получает доступ к общей state directory):

```bash
sudo systemctl stop hermes-signals-bot.timer
sudo systemctl stop hermes-signals-bot.service
sudo install -o root -g root -m 0644 /opt/hermes-trading/app/deploy/systemd/hermes-signals-bot.service /etc/systemd/system/hermes-signals-bot.service
sudo install -o root -g root -m 0644 /opt/hermes-trading/app/deploy/systemd/hermes-levels-bot.service /etc/systemd/system/hermes-levels-bot.service
sudo systemctl daemon-reload
sudo systemd-analyze verify /etc/systemd/system/hermes-signals-bot.service /etc/systemd/system/hermes-levels-bot.service
sudo systemctl enable --now hermes-levels-bot.service
sudo systemctl status hermes-levels-bot.service
sudo journalctl -u hermes-levels-bot.service -n 50 --no-pager
sudo systemctl enable --now hermes-signals-bot.timer
```

`StateDirectory=hermes-trading` создаёт `/var/lib/hermes-trading` с правами 0700
для пользователя `hermes`. SQLite создаётся демоном, схема имеет явную версию.
Другой путь требует разрешения записи в systemd override для обоих services;
не отключайте `ProtectSystem=strict` целиком.

Демон работает в foreground под systemd, без `&`, cron или daemonize.
Он принимает команды круглосуточно. Входящий порт не нужен.

Один токен должен иметь только одного потребителя updates. Не запускайте
параллельно `get_telegram_chat_id` или локальный listener с production-токеном.
Файловая блокировка защищает от двух процессов с одной базой. Telegram 409
(второй poller или webhook) останавливает демон с кодом 78; он не удаляет webhook
самостоятельно. 401/404 также требуют исправления конфигурации.

Long polling ждёт до 30 секунд, сетевой timeout — 40 секунд. SIGTERM/SIGINT
останавливают цикл после текущего запроса; systemd даёт 60 секунд.
Сетевые ошибки повторяются с задержкой 1–60 секунд, 429 учитывает `retry_after`.
Сбои базы не подтверждают необработанную команду. После исправления конфигурации:

```bash
sudo systemctl reset-failed hermes-levels-bot.service
sudo systemctl restart hermes-levels-bot.service
```

Отправьте `/help`, добавьте тестовый уровень, проверьте `/levels`, перезапустите
service и убедитесь, что запись сохранилась, затем удалите её. Это ручная проверка
с реальными сообщениями; автоматические тесты не используют Telegram или биржу.

## Перезапуски и доставка

Изменение уровней, идентификатор обработанного update, курсор и очередь ответов
фиксируются одной транзакцией. После перезапуска повторный update не выполняется.
Отпечатки updates сохраняются без полного исходного сообщения. При длительном
простое устаревший offset сбрасывается, поскольку Telegram может сменить порядок
идентификаторов. Детали API: [getUpdates](https://core.telegram.org/bots/api#getupdates).

Перед отправкой ответ помечается как `attempted`. После неоднозначного сетевого
сбоя он не отправляется заново: возможна потеря подтверждения, но не повторное
выполнение команды. Проверьте `/levels`. Ошибки отправки и незавершённые попытки
видны в journald. Явное отклонение 429 допускает повтор после заданной задержки.
Ограничения доставки описаны в [ADR-001](adr/adr-001-manual-price-areas.md).

Не удаляйте таблицы обработанных updates или курсор для «исправления» доставки.
Одна база привязана к ID бота; смена токена того же бота допустима, смена самого
бота требует отдельной базы/осознанной миграции.

## Обновление, резервная копия и откат

`deploy/update-server.sh` останавливает уже включённый/работающий listener до
обновления кода и запускает после проверки units. При первой установке он
устанавливает unit, но не включает демон до настройки allowlist и базы.
При ошибке обновления listener и timer остаются остановленными; после
восстановления нужно проверить и вручную запустить listener.
База и env не перезаписываются.

Регулярно сохраняйте закрытую резервную копию базы вне сервера. SQLite работает
в WAL-режиме: копирования только основного файла во время работы недостаточно.
Пример online-backup через стандартный Python (каталог backups — вне Git):

```bash
sudo install -d -o hermes -g hermes -m 0700 /var/lib/hermes-trading/backups
sudo -u hermes /opt/hermes-trading/app/.venv/bin/python -c 'import os, sqlite3; os.umask(0o077); source = sqlite3.connect("file:/var/lib/hermes-trading/levels.sqlite3?mode=ro", uri=True); target = sqlite3.connect("/var/lib/hermes-trading/backups/levels.sqlite3"); source.backup(target); target.close(); source.close()'
```

Для восстановления остановите listener, timer и выполняющийся scanner. Сохраните
старую базу вместе с `-wal`/`-shm` в отдельный каталог; восстанавливайте snapshot
в чистый путь без старых WAL-файлов, с владельцем `hermes` и правами 0600.
Старый snapshot не содержит изменений после backup: проверьте актуальные уровни.
Не запускайте миграции старой версией приложения.

Отключить функцию можно без удаления данных:

```bash
sudo systemctl disable --now hermes-levels-bot.service
```

Очистите `LEVELS_DB_PATH` в environment, чтобы scanner перестал читать уровни.
Для отката кода сначала остановите timer и текущий scan, затем используйте
обычный процесс восстановления версии. Храните базу для последующего возврата.

## Локальный запуск

Загрузите отдельную тестовую конфигурацию из окружения, задайте allowlist и путь
вне репозитория, затем запустите `python3 src/levels_bot.py`. Используйте отдельный
тестовый бот, если production listener уже работает с основным токеном.

## Проверить совпадение уровня с паттерном

После добавления уровня через Telegram откройте второй терминал в корне проекта
и загрузите тот же `.env`, чтобы использовать ту же `LEVELS_DB_PATH`:

```bash
set -a
source .env
set +a

python3 src/scan_signals.py \
  --exchange bingx \
  --symbols BTC/USDT \
  --timeframes 15m \
  --date-from '2026-09-24 09:00' \
  --date-to '2026-09-24 12:00' \
  --check-levels \
  --no-metric-filter
```

Замените пример дат нужным периодом. Время без смещения теперь по умолчанию
считается в **Europe/Madrid — местном времени Барселоны**, с переходом на летнее
время. Можно указать `--timezone UTC` или явное смещение (`+02:00`, `+01:00`, `Z`).
Конкретное конечное время не включается; конечная дата без времени включает весь
локальный день. Проверяется время закрытия последней свечи паттерна.

Сначала выводится список активных областей выбранной биржи/тикера. Для каждого
паттерна затем выводятся диапазон с тенями и `Matched current area: #...` либо
`Current levels: no match`. Итог: `Patterns matching current levels: N/M`.

Для `/levels_add BTC/USDT bingx buy 15m level 83847` совпадение требует LONG
паттерна на BingX BTC/USDT, чей полный диапазон включает 83847. Касание цены без
паттерна не создаёт совпадения. `--no-metric-filter` позволяет проверить все
паттерны независимо от объёма и волатильности. Таймфрейм источника уровня не
ограничивает таймфреймы проверяемых сигналов.

Это проверка **текущих** активных областей на прошлых свечах: состояние уровней
на историческую дату не восстанавливается. Данные читаются перед сканированием,
записи и статус уровней не меняются. Демон можно оставить работающим.

По умолчанию результат виден только в терминале. С `--send-telegram` сообщения
также поступят в настроенный чат с пометкой `Historical scan — current levels test`.
Без `--check-levels` ручной скан продолжает искать только паттерны.
